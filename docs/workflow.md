# Как работаем

Процесс повторяет командную разработку: ветки, Pull Request, код-ревью. Это тоже часть обучения.

## Цикл одной задачи

1. **Получить свежую версию**
   ```bash
   git checkout main
   git pull
   ```
2. **Создать ветку под задачу**
   ```bash
   git checkout -b 01-obj-analyzer-stage1
   ```
3. **Писать код**, коммитить небольшими логическими шагами:
   ```bash
   git add .
   git commit -m "Парсинг вершин и граней"
   ```
4. **Отправить ветку на GitHub**
   ```bash
   git push -u origin 01-obj-analyzer-stage1
   ```
5. **Открыть Pull Request** на GitHub (кнопка *Compare & pull request*).
6. **Попросить Claude сделать ревью**: прислать ссылку на PR.
7. **Исправить замечания**: новые коммиты в ту же ветку, PR обновится сам.
8. **Слить PR** в `main` (*Merge pull request*), обновить статус в `README.md`.

## Именование веток

`<номер проекта>-<коротко>-<этап>`, например `03-shaft-calc-stage2`.

## Сообщения коммитов

Коротко, в повелительном наклонении, что сделано: «Добавить расчёт объёма», «Исправить парсинг f v//vn».

## Когда застрял

Спросить Claude. Подсказки идут по ступеням: вопрос → намёк → фрагмент кода.
Готовое решение — только по явной просьбе.
